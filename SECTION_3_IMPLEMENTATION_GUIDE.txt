1. SECTION 3 OVERVIEW
================================================================================

WHAT: Section 3 implements message conversion between ROS2 and RIX formats

GOAL: Create translator functions that convert String messages bidirectionally:
  - ROS2 std_msgs/String ↔ RIX rix.msg.standard.String

DELIVERABLES:
  ✓ Base converter interface (MessageConverter class)
  ✓ String converter implementation (StringConverter class)
  ✓ Unit tests for all conversion functions

ANALOGY: Like building a dictionary for translating English ↔ Spanish
  - The base converter is the template for dictionary entries
  - The String converter is one specific entry in the dictionary
  - Tests verify the translations are accurate

================================================================================
2. WHY MESSAGE CONVERTERS?
================================================================================

PROBLEM:
  ROS2 and RIX are two different middleware systems. They speak different
  "languages" - their message formats are different even when representing
  the same data.

  Example:
    - Both have a "String" message type
    - Both store text data
    - But they are DIFFERENT Python classes
    - You cannot directly pass a ROS String to RIX (or vice versa)

SOLUTION:
  Create converter functions that translate between the two formats by:
    1. Creating a new message object of the target type
    2. Copying data from source fields to target fields
    3. Returning the translated message

WHEN USED:
  - Section 4 (Bridge Handles) will call these converters
  - Every time a message crosses from ROS→RIX or RIX→ROS
  - The converter translates it so the receiving side can understand it

WHY SEPARATE FROM BRIDGE LOGIC:
  - Clean separation of concerns (translation vs. message passing)
  - Easy to test conversion logic independently
  - Easy to add new message types without modifying bridge code
  - Follows software engineering best practices

================================================================================
3. ARCHITECTURE OVERVIEW
================================================================================

COMPONENT HIERARCHY:

  MessageConverter (Base Class)
        │
        │ defines interface
        │
        ▼
  StringConverter (Concrete Class)
        │
        │ implements conversion
        │
        ├─→ ros_to_rix()  : Converts ROS String → RIX String
        └─→ rix_to_ros()  : Converts RIX String → ROS String

WHY THIS STRUCTURE?
  - Base class ensures all converters have the same interface
  - Makes it easy to add new message types later (Point, Pose, etc.)
  - Bridge code can use any converter without knowing implementation details

CONVERSION FLOW (ROS→RIX):
  1. Receive ROS String message
  2. Create new RIX String instance
  3. Copy data field
  4. Return RIX message

  1. Receive RIX String message
  2. Create new ROS String instance
  3. Copy data field
  4. Return ROS message

WHY SO SIMPLE?
  String messages only have one field ('data')
  Both types store plain Python strings
  No complex transformations needed

FUTURE COMPLEXITY:
  For messages like Pose or Header, would need to:
  - Convert multiple fields
  - Handle nested messages
  - Transform timestamps (sec/nsec vs sec/nanosec)

7. HOW IT ALL WORKS TOGETHER
================================================================================

COMPONENT INTERACTION:

1. BASE INTERFACE (converters/__init__.py)
   ↓
   Defines: "All converters must have ros_to_rix() and rix_to_ros()"
   
2. CONCRETE IMPLEMENTATION (converters/std_msgs.py)
   ↓
   Implements: "Here's how to convert String messages"
   
3. TESTS (test/test_converters.py)
   ↓
   Verifies: "The implementation works correctly"


EXAMPLE USAGE (in future Section 4):

  # Bridge handle receives ROS message
  def ros_callback(ros_msg):
      # Use converter to translate
      rix_msg = StringConverter.ros_to_rix(ros_msg)
      # Publish to RIX
      rix_publisher.publish(rix_msg)


DATA FLOW IN ACTION:

  ROS Publisher sends:
    RosString(data="Hello World")
    
        ↓ (arrives at bridge)
        
  StringConverter.ros_to_rix(ros_msg):
    1. Create RixString()
    2. Copy: rix_msg.data = ros_msg.data  # "Hello World"
    3. Return rix_msg
    
        ↓ (publish to RIX)
        
  RIX Subscriber receives:
    RixString(data="Hello World")


REVERSE DIRECTION:

  RIX Publisher sends:
    RixString(data="Hello ROS")
    
        ↓ (arrives at bridge)
        
  StringConverter.rix_to_ros(rix_msg):
    1. Create RosString()
    2. Copy: ros_msg.data = rix_msg.data  # "Hello ROS"
    3. Return ros_msg
    
        ↓ (publish to ROS)
        
  ROS Subscriber receives:
    RosString(data="Hello ROS")
